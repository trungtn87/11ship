## 3. Technology locked

- NestJS 11 / Express adapter.
- PostgreSQL through `pg`; no ORM.
- Existing node-pg-migrate workflow.
- Jest integration/unit setup already in repo.
- Opaque bearer token: 32 random bytes, base64url; DB stores SHA-256 digest only.
- Verification proof token: 32 random bytes, base64url; DB stores SHA-256 digest only.
- Password: `argon2` package, Argon2id with ADR-002 parameters:
  - memoryCost = 19456 KiB
  - timeCost = 2
  - parallelism = 1
- OTP: 6 ASCII digits generated by CSPRNG; DB stores HMAC-SHA-256 digest, never plaintext.

Add `argon2` as an exact dependency and update lockfile. Do not add an ORM, validation framework, JWT library or crypto package.

## 4. Phone contract

A1 supports Vietnamese mobile numbers.

Accepted forms after outer whitespace trim:

- `0XXXXXXXXX`
- `84XXXXXXXXX`
- `+84XXXXXXXXX`

The subscriber part is 9 ASCII digits. Normalize to `+84XXXXXXXXX`.

Reject malformed/non-ASCII phone input with `INVALID_PHONE`.

Password is never trimmed, Unicode-normalized or altered.

## 5. Database schema

Create one new Auth migration after the M00 migrations. No `IF NOT EXISTS` drift masking and do not edit applied migrations.

### users

Minimum:

- `user_id uuid PK`
- `phone_normalized varchar(...) UNIQUE NOT NULL`
- `password_hash text NOT NULL`
- `phone_verified_at timestamptz NOT NULL`
- `status ACTIVE | DISABLED`
- `version bigint NOT NULL DEFAULT 1 CHECK >= 1`
- `created_at`
- `updated_at`

### user_roles

- `user_id` FK -> users
- `role` bounded UPPER_SNAKE token
- `created_at`
- UNIQUE `(user_id, role)`

A1 service supports only SHOP and DRIVER role selection. Do not create ADMIN/SYSTEM/PLATFORM roles. PLATFORM is a driver classification, not an Auth role.

### phone_verifications

Minimum:

- `verification_id uuid PK`
- `phone_normalized`
- `purpose` (A1 supports REGISTER)
- `otp_digest char(64)`
- `status`: PENDING_DELIVERY | PENDING | VERIFIED | LOCKED | INVALIDATED | DELIVERY_FAILED
- `attempt_count >= 0`
- `expires_at`
- `resend_not_before`
- `verified_at nullable`
- `invalidated_at nullable`
- `created_at`

Index for latest verification by `phone_normalized,purpose,created_at`.

### verification_proofs

Minimum:

- `proof_id uuid PK`
- `verification_id uuid UNIQUE FK`
- `phone_normalized`
- `purpose`
- `token_digest char(64) UNIQUE`
- `expires_at`
- `consumed_at nullable`
- `invalidated_at nullable`
- `created_at`

A1 does not delete proof rows. They must remain resolvable after natural expiry or consumption for idempotent register replay.

### sessions

Minimum:

- `session_id uuid PK`
- `user_id uuid FK`
- `token_digest char(64) UNIQUE NOT NULL`
- `device_id` bounded client label; it is not an authentication factor
- `platform` bounded token
- `app` bounded token
- `active_role nullable`
- `expires_at`
- `revoked_at nullable`
- `created_at`
- `updated_at`

Add a partial unique index that prevents two unrevoked SHOP-context sessions for one user:

`UNIQUE(user_id) WHERE active_role='SHOP' AND revoked_at IS NULL`

Expiry does not appear in the index. SHOP selection revokes any older unrevoked SHOP context before activating the new one.

## 6. Config

Centralized config:

- `AUTH_OTP_TTL_SECONDS=300`
- `AUTH_OTP_RESEND_SECONDS=60`
- `AUTH_OTP_MAX_ATTEMPTS=5`
- `AUTH_PROOF_TTL_SECONDS=600`
- `AUTH_SESSION_TTL_SECONDS=604800`
- `AUTH_OTP_HMAC_SECRET`: base64 of exactly 32 bytes

Suggested bounds:

- OTP TTL 30..600 s
- resend 1..300 s
- max attempts 1..10
- proof TTL 60..1800 s
- session TTL 300..2592000 s

Invalid config reports variable names only.

Argon2 parameters are constants from ADR-002 in A1, not downgradeable ENV values.

OTP request A1 enforces the locked 60-second cooldown transactionally by phone + purpose. Do not invent an additional global IP/device quota whose threshold has not been specified. Edge/global abuse throttling can be added separately; `OTP_RATE_LIMITED` covers cooldown and locked verification attempts in A1.

## 7. OTP provider boundary

Define `OtpProvider` port. No production SMS adapter in A1.

A fake provider is permitted only in test/development and must never log the OTP. No silent fake fallback in staging/production.

OTP delivery must happen outside a DB transaction.

Request flow:

1. transactionally serialize the phone+purpose request and enforce resend cooldown;
2. create a PENDING_DELIVERY verification with HMAC digest and commit;
3. call `OtpProvider` outside the transaction;
4. on success, short transaction marks PENDING;
5. on provider failure, short best-effort transaction marks DELIVERY_FAILED/INVALIDATED and return sanitized 503.

A failed delivery must not become a usable verification and must not permanently block a retry.

## 8. OTP digest and verify

HMAC input must unambiguously bind:

`verification_id + phone_normalized + purpose + otp`

using the configured 32-byte secret and HMAC-SHA-256.

Verify endpoint locks the verification row and uses fresh PostgreSQL time.

- wrong OTP: increment attempts;
- attempt reaching max: LOCKED and `OTP_RATE_LIMITED`;
- expired: `OTP_EXPIRED`;
- VERIFIED/INVALIDATED/LOCKED reuse: typed contract error;
- valid OTP: mark VERIFIED and create one proof in the same transaction.

Compare HMAC digests constant-time. Never log OTP/digest.

## 9. Register — authoritative M00-C1 integration

Endpoint:

`POST /v1/auth/register`

requires canonical `Idempotency-Key`.

Strict request keys only:

- phone
- password
- verification_token
- device { device_id, platform, app }

Security-sensitive unknown fields such as role, driver_type, is_admin, permissions must be rejected. No role is created by register.

### 9.1 Resolve before idempotency

Parse the proof token and resolve by digest before executing the idempotency coordinator.

Resolution MUST still find a proof that is:

- consumed;
- naturally expired;
- invalidated.

This lookup establishes server-side proof identity. It must not reject consumed/natural-expired proof before idempotency lookup.

Wrong purpose -> `VERIFICATION_PURPOSE_MISMATCH`.  
Unknown/binding-invalid token -> `VERIFICATION_PROOF_INVALID`.

Idempotency identity:

- scope_type = `verification_proof`
- scope_id = `proof_id`
- operation_id = `auth.register.v1`

Logical request is exactly the validated:

- phone_normalized
- password with original semantics
- verification_token
- all device fields

### 9.2 Password hashing

Argon2id hashing is CPU work and must not unnecessarily hold PostgreSQL business locks.

Hash the validated password before entering the idempotency transaction. A replay may perform an unused hash; correctness is preferred over holding an advisory/DB transaction around Argon2.

### 9.3 New execution callback

Lock order after the idempotency lock:

1. proof FOR UPDATE;
2. user/business state;
3. session when created/read.

Under fresh DB time:

- proof must not be invalidated;
- proof must be unused;
- proof must be unexpired;
- purpose REGISTER and phone binding must match.

Then:

- create unique ACTIVE user;
- consume proof;
- generate access token;
- create roleless session with absolute expiry;
- append SUCCESS audit;
- append `auth.user_registered.v1` outbox event;
- return 201 result to the IdempotencyExecutor.

All DB effects above plus the encrypted idempotency record commit atomically.

Concurrent register with another valid proof/key for the same phone must leave exactly one user. Map the losing unique-phone race to `PHONE_ALREADY_REGISTERED`; do not expose SQL.

### 9.4 Replay guard

Register replay is sensitive.

Persist replay guard with only non-secret IDs:

- proof_id
- user_id
- session_id

Authorization hook uses the SAME TransactionContext and locks in order:

1. proof FOR UPDATE;
2. user FOR UPDATE;
3. session FOR UPDATE.

Checks:

- invalidated proof -> `VERIFICATION_PROOF_INVALID`;
- natural proof expiry alone does NOT deny committed replay;
- user not ACTIVE -> `ACCOUNT_DISABLED`;
- session wrong binding/revoked -> `SESSION_REVOKED`;
- session expired at fresh DB time -> `SESSION_EXPIRED`.

Only after the hook returns true may M00 decrypt the stored result.

Do not mint a new token during replay.

## 10. Session token/authentication

Access token:

- 32 CSPRNG bytes;
- canonical base64url;
- plaintext returned once to client;
- only SHA-256 digest stored.

Authorization header:

`Authorization: Bearer <token>`

Malformed/missing/unknown bearer -> `SESSION_INVALID`.

Every protected request checks:

- exact session digest;
- revoked_at;
- expiry using DB time;
- user status.

Errors:

- revoked -> `SESSION_REVOKED`
- expired -> `SESSION_EXPIRED`
- disabled -> `ACCOUNT_DISABLED`

No token is accepted from query parameters.

## 11. Login

`POST /v1/auth/login`

Phone-not-found and wrong password both return `INVALID_CREDENTIALS`.

Use a dummy Argon2 verification path for a missing user to avoid an obvious existence timing split.

For an existing user:

1. read password hash;
2. verify Argon2 outside transaction;
3. short transaction locks/rechecks user is ACTIVE and password hash has not changed;
4. create a new roleless session (`active_role=NULL`);
5. append SUCCESS login audit;
6. commit, then return access token.

If correct credentials belong to a disabled account -> `ACCOUNT_DISABLED`.

Login never auto-selects a role. It returns sorted available SHOP/DRIVER roles:

- no roles -> `onboarding_required=true`
- one or more roles -> `role_selection_required=true`

## 12. Role selection and SHOP single-device

`POST /v1/auth/role/select` is bearer protected.

A1 selectable roles: SHOP and DRIVER only.

ADMIN, SYSTEM, PLATFORM, unknown roles, or a role absent from `user_roles` -> `ROLE_NOT_AVAILABLE`.

Transaction lock order:

1. user FOR UPDATE;
2. current session FOR UPDATE;
3. read/lock user role membership as needed.

Re-check current session has not been revoked/expired and user ACTIVE inside the transaction.

For SHOP:

- revoke every other unrevoked session for the same user with `active_role='SHOP'`;
- activate SHOP on the current session;
- partial unique index is the final safety net;
- write audit in the same transaction.

For DRIVER:

- set current session active_role=DRIVER;
- do not revoke other DRIVER sessions;
- do not revoke another device's DRIVER session merely because SHOP moved.

Concurrent SHOP selections may both return success sequentially, but after they finish there must be exactly one unrevoked SHOP-context session. The earlier winner must then fail protected requests with `SESSION_REVOKED`.

A1 uses `user_roles` as the available-role source. M02/M03 profile-state eligibility is added with onboarding/module ownership in A2; business endpoints must still enforce their own current profile/status later.

## 13. /me

`GET /v1/auth/me` is bearer protected.

Return:

- user_id
- phone_normalized
- sorted available_roles limited to supported business roles
- active_role
- onboarding_required when no roles
- role_selection_required when roles exist and active_role is null

Do not fabricate SHOP/DRIVER onboarding state before M02/M03 exist.

## 14. Audit / outbox

Reuse M00 writers; do not create another audit/event subsystem.

Mandatory transactional audit:

- register SUCCESS;
- login SUCCESS;
- role select SUCCESS;
- SHOP session replacement/revocation as part of role select.

Use safe metadata only; never phone/password/hash/OTP/proof/access token/Authorization.

Register emits one outbox event:

- event_type = `auth.user_registered.v1`
- schema_version = 1
- resource_type = `user`
- resource_id = user_id
- resource_version = 1
- payload contains only safe non-secret identifiers needed by future consumers.

Replay does not emit a second audit/outbox event because the business callback is not rerun.

Standalone DENIED audit may be used for OTP locked/rate-limited and disabled-account login attempts. It must never alter the original Auth error.

## 16. Required acceptance

Keep legacy A01-01..A01-11 and A02-12..A02-19, plus these mandatory expansions.

### Register/idempotency

- same key + same request -> exact logical replay, callback not rerun;
- first response lost after commit -> retry replays;
- replay works with consumed proof;
- natural proof expiry after commit but inside replay TTL still replays;
- same key with changed password/device/phone -> `IDEMPOTENCY_KEY_REUSED`;
- revoked session -> replay denied `SESSION_REVOKED`;
- disabled user -> replay denied `ACCOUNT_DISABLED`;
- invalidated proof -> replay denied `VERIFICATION_PROOF_INVALID`;
- replay TTL expired -> `IDEMPOTENCY_REPLAY_EXPIRED`, no mutation;
- key rotation regression uses the record's historical key;
- dedupe expiry does not bypass proof-used + unique-phone business invariants.

### Concurrency

- same proof + different keys concurrently: one register; loser sees proof-used; one user/session effect;
- different valid proofs + different keys for same phone concurrently: one user; loser `PHONE_ALREADY_REGISTERED`;
- concurrent SHOP select on two sessions -> final exactly one unrevoked SHOP session;
- DRIVER session stays valid during SHOP switch.

### Security/privacy

- no plaintext password, OTP, verification token, access token or Authorization in DB/log/audit/outbox;
- DB stores Argon2 PHC password hash, OTP HMAC digest, proof/session SHA-256 digests;
- forbidden role/driver_type/admin fields never create privilege;
- bearer revoked/expired/disabled checks pass through the real Nest HTTP pipeline.

### Atomicity

Fault injection at user/proof/session/audit/outbox/idempotency persistence must prove register transaction leaves no partial business/infrastructure effects.
