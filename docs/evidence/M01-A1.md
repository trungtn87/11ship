## Migration `1791504000000_create-auth-core.sql`

Tables `app.users`, `app.user_roles`, `app.phone_verifications`, `app.verification_proofs`, `app.sessions`; no
`IF [NOT] EXISTS`, no seed data, no edit of any applied migration. Down drops in reverse dependency order without
CASCADE. Key DB-enforced invariants: `users.phone_normalized` UNIQUE; Argon2id PHC prefix check; proof one per
verification and unique token digest; session token digest unique; partial unique index
`sessions_active_shop_per_user_uq ON app.sessions(user_id) WHERE active_role='SHOP' AND revoked_at IS NULL`.
Proofs are never deleted so a committed register stays replayable.

## Design summary

- Argon2id memory 19456 KiB, timeCost 2, parallelism 1 (constants, not env). Password never trimmed or
  normalized. Hash happens before the idempotency transaction; login verification outside any transaction.
- OTP: 6 digits from a CSPRNG; digest `HMAC-SHA-256` over canonical JSON
  `["11ship.auth.otp.v1", verification_id, phone, purpose, otp]`, constant-time compare. Lane lock domain
  `11ship.auth.otp.request.v1`; only the 60 s per phone+purpose cooldown (no IP/device/daily throttles).
- Provider is called outside any transaction (5 s timeout); `PENDING_DELIVERY` commits first; failure marks
  `DELIVERY_FAILED` and returns a sanitized 503. Wrong-OTP and LOCKED transitions commit; the typed error is thrown
  after commit.
- Register lock order: idempotency advisory lock → proof `FOR UPDATE` → user insert (`ON CONFLICT DO NOTHING`;
  conflict → `PHONE_ALREADY_REGISTERED`) → consume proof → session → audit → outbox. The replay hook locks proof,
  user, session in that order and does not deny a replay because the proof expired naturally.
- Role select lock order: user → session → fresh clock → role check; SHOP revokes other unrevoked SHOP sessions,
  the partial unique index is the safety net. Session check order: revoked → expired → disabled. Bearer only.
- `OtpHmacKey` redacts under `toJSON`/`toString`/`inspect`. Production/staging refuse to boot (`OTP_PROVIDER`
  named) because no SMS adapter exists. Server startup now needs `AUTH_OTP_HMAC_SECRET` plus the existing crypto
  keyring variables (documented in `.env.example` and README).
- 15 new typed error codes (registry now 22) with the locked statuses; fixed messages never echo input.
