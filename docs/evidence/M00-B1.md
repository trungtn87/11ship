## Implemented contract

- `GET /v1/health/live` → 200 `{"data":{"status":"ok"}}`, independent of DB availability.
- `GET /v1/health/ready` → 200 `{"data":{"status":"ready"}}` after checked `SELECT 1`; DB failure → 503 `SERVICE_UNAVAILABLE`.
- Error envelope: `{"error":{"code","message","request_id","details":{}}}`.
- Server-generated UUID request ID returned in `X-Request-ID`; client request IDs are not reflected.
- Logs emit only whitelisted metadata; raw exception messages, path/query, DSN, SQL and credentials are not logged.
- Config requires `APP_ENV` and `DATABASE_URL`; invalid config exits nonzero while printing variable names only.
- PostgreSQL pool is lazy, bounded by connect/query timeouts and closes on application shutdown.
- Migrations are explicit (`npm run db:migrate`), not run at application startup.
- Integration tests verify the connected database and server-reported user before DDL; there is no override flag.
