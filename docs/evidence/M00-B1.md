## What the code implements

- `GET /v1/health/live` → 200 `{"data":{"status":"ok"}}`, no DB query.
- `GET /v1/health/ready` → `SELECT 1` and its result checked; 200 `{"data":{"status":"ready"}}`, or 503
  `SERVICE_UNAVAILABLE`.
- Error envelope `{"error":{"code","message","request_id","details":{}}}`. Fixed messages per status; the
  original exception message is never used. Unknown route → 404 `NOT_FOUND`; anything unexpected → 500
  `INTERNAL_ERROR`.
- Server-generated UUID `request_id`, returned as `X-Request-ID`. A client-sent `X-Request-ID` is ignored.
- Logs: one JSON line, only whitelisted keys (`request_id`, `method`, `status`, `code`, `duration_ms`, `port`,
  `error_class`); no path, query, DSN, SQL or error message.
- Config: `APP_ENV` required enum; `NODE_ENV` must be development/test/production; `DATABASE_URL` required with
  no fallback in any environment; `PORT` 1..65535 default 3000; `HOST` default 127.0.0.1; pool max 1..50,
  timeouts 100..30000 ms (defaults 10 / 1000 / 1000). Bad config exits nonzero naming only the variables.
- Pool is created lazily, has an `error` listener that logs a short code, and is closed after the HTTP server.
  Startup neither connects to the DB nor migrates.
- `npm run db:migrate` runs `node-pg-migrate up` with its lock enabled. No reset or destructive command exists.
- Integration guard: `APP_ENV=test`, and the server-reported `current_database()` and `current_user` must both be
  `ship11_test`, checked with a SELECT before any DDL. There is no override flag.

## Known gaps and decisions

1. **No lockfile.** `package-lock.json` could not be generated. CI uses `npm ci` and will fail until it is committed.
2. **Unverified API assumptions** (written from knowledge of the libraries, not run): `node-pg-migrate` 8 CLI flags
   `up`, `--migrations-dir`, `--migrations-schema`, `--create-migrations-schema`, the `-- Up Migration` /
   `-- Down Migration` SQL markers and the `pgmigrations` history table; Node's `--env-file-if-exists` and
   `process.loadEnvFile`; NestJS 11 behaviour that Express 404s reach the global filter, that `app.use` runs before
   routes, and that shutdown hooks run after the HTTP server is closed; Jest 30 `globalSetup` default-export interop.
3. **F03 covers `up` twice only.** The `down` section exists but is untested, because tests may only drop the random
   schema they created and the smoke migration creates the fixed schema `app`.
4. **F06 user mismatch** is covered by fake-query unit tests only. The real-database mismatch connects the test user to
   the `postgres` database and relies on that connection being allowed.
5. **F02b** uses a refused port. A non-routable address (to exercise the connect timeout itself) is not tested.
6. **`npm run dev`** builds then runs once; it does not watch for changes.
7. **CI role setup.** The service container's admin account is used only to create the restricted `ship11_test` role
   (`NOSUPERUSER NOCREATEDB NOCREATEROLE`), owner of the `ship11_test` database only. The password literals in the
   workflow belong to a throwaway container.
8. No backup or restore was tested (`ops/runbooks/database-backup-restore-guidance.md` is guidance only).
9. No Auth, Shop, Driver, Wallet or Delivery code, no frontend, no SMS, no production resources.
